Main window layouts

For review. Nothing here is in the design system yet.

At this window size the Preview column is 310 × 613 px, but all it draws is a 286 × 161 frame and the 34 px Actual size bar. The frame can’t grow taller: the code fits it to the column’s width at the game’s shape (1920 × 1080 when no game is running), so the rest stays empty. Each sample gives that height to something else. Same window, same controls; only C adds a menu item. All four show five cooldowns (four made up) so the lists show how they fill.

What moves

  • The preview runs from the top of the window to the status bar.
  • The frame is fitted to the column’s width, so it sits in the middle of a tall, mostly empty well (about 60 % of it).

What you get

  • The frame and the Actual size bar are always in view while you edit anything.

What it costs

  • Overlay bar settings sit in the detail column, away from the bar they change.
  • Show advanced stacks five more rows under Timing; the list drops to 3 rows and the window still grows 116 px.

Code

  • layout_preview sizes the well to the status bar.
  • preview_canvas fits the frame to the width (16:9 at 1920 × 1080 when no game runs).

What moves

  • Overlay bar settings go under the preview.
  • The preview shrinks to its frame plus the Actual size bar.
  • Timing and key and Visual trigger sit side by side under the cooldowns; the list takes the rest of the height.

What you get

  • Change Fill or Height and see it right above.
  • The cooldown list shows 12 rows instead of 6.
  • Show advanced fits without growing the window: the list gives up rows instead.

What it costs

  • The well stays 16:9; a 4:3 or ultrawide game letterboxes inside it as it does now, so the settings don’t jump when the game starts.
  • Tab order: move the three Preview lines above Overlay bar in editor_resources.rc so Tab runs top to bottom.
  • Below 1100 px it falls back to today’s narrow layout.

Code

  • layout_preview: well height = frame + Actual size strip.
  • layout_overlay: called with the preview column, under the well.
  • layout_cooldowns: Timing | Visual trigger side by side; drop the 180 px list cap.
  • No new controls.

What you get

  • The most room for the list and fields.
  • Reuses the narrow-window code path.
  • With A: the bar column when on, this when off.

What it costs

  • Without the preview you see the bar’s look and place only in game, through Position on window; the Actual size bar goes too.
  • An empty block right of the cooldown buttons.
  • One more setting to remember.

Code

  • New IDM_VIEW_PREVIEW item, saved like Text Size.
  • make_main_layout: preview = setting and width ≥ 1100.
  • layout_cooldowns: three columns when wide enough.
